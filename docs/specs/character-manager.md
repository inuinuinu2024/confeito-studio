# Character Manager と登録キャラクター

ユーザーが登録したキャラクターを、全ツールで共有する 1 つの一覧として管理する。
管理は Character Manager（左端の表示モード）で行い、ツール（今は Nano Banana画像生成）からは呼び出し（使う）だけを行う
（ツール側の操作は [tools/gemini-image.md](./tools/gemini-image.md)「登録したキャラクター」）。
画面と操作の多くは [prompt-manager.md](./prompt-manager.md) と同じ。この文書では違う点を中心に書く。

## データ
- 1 件 = **名前・カテゴリー・プロンプト本文・画像（画像ごとの本文つき）**（＋自動の id、＋任意のアイコン）。ツールごとに分けず、全ツールで同じ一覧を使う。
- **名前**: 前後の空白を除いて 1〜100 文字。**全体で一意**（キャラクターの中で。プロンプトとは別）。大文字・小文字、全角・半角は区別する。
- **カテゴリー**: Prompt Manager と同じ決まり（自由入力・0〜50 文字・空なら「未分類」・使われなくなったカテゴリーは消える）。
  カテゴリーの一覧はプロンプトとは別（同じ名前のカテゴリーがあっても関係しない）。
- **プロンプト本文**: 任意（空でもよい）。前後の空白もそのまま保存する。キャラクター全体に共通の特徴（髪型・服装など）を書く。
- **画像ごとの本文**: 画像 1 枚ごとに任意の本文（「正面を向いた全身」「横顔」など、その画像だけの説明）。空でもよい。
  画像を外すとその本文も消える。ツールで使う時の扱いは [tools/gemini-image.md](./tools/gemini-image.md)「登録したキャラクター」。
- **画像**: 0 枚以上（上限なし）。1 つのキャラクターに複数の画像を順番付きで持つ。
  - 形式は PNG / JPEG / WebP（ファイルの中身で判定する）。それ以外は追加しない。
  - 追加したファイルをそのまま保存する（縮小・変換しない。Gemini に送る時の縮小はツール側で行う）。
- **アイコン**: 任意。キャラクターの画像から顔の部分を切り取った **256×256 の PNG**（作り方は下の「アイコン」）。
  - 一覧で名前の横に出すためのもの。**画像（`images`）には含めない**ので、ツールでキャラクターを使っても参照画像として送られない。
  - 元の画像とは別のファイルとして持つ（元の画像を外してもアイコンは残る）。
- 保存に必須なのは名前だけ（本文だけ・画像だけのキャラクターも作れる）。
- **並び順**: キャラクターもカテゴリーも手動で並べ替える。新しいもの（新規・インポート・カテゴリー変更で移ったもの）は末尾に入る。
  「すべて」は先頭、「未分類」は常に最後。

### 保存先
- `assets/characters/`（git 管理外・ユーザーデータ。`CONFEITO_ASSETS_DIR` で `assets/` の場所を変えられる）。バックエンドの起動時に作る（なければ）。
  ```
  assets/characters/
  ├ characters.json
  ├ <キャラクターの id>/
  │  ├ <画像の id>.png
  │  ├ <画像の id>.jpg
  │  └ icon-<自動の id>.png   ← アイコン（あれば）
  └ …
  ```
  ```json
  {
    "categories": ["主要キャラ"],
    "characters": [
      { "id": "<自動>", "name": "花子", "category": "主要キャラ", "text": "黒髪ボブ、赤いリボン",
        "images": ["<画像の id>.png", "<画像の id>.jpg"], "image_texts": { "<画像の id>.png": "正面を向いた全身" },
        "icon": "icon-<自動の id>.png" }
    ]
  }
  ```
  - `categories` はカテゴリーの並び順（「未分類」は含めない）、`characters` は全体の並び順、`images` は画像の並び順（ファイル名）。
  - `image_texts` は画像ごとの本文（画像のファイル名 → 本文。本文のある画像だけ）。`images` にない画像の本文・文字列でない本文は読む時に外す。
    以前の版のファイル（`image_texts` がない）は、どの画像も本文なしとして読む。
  - `icon` はアイコンのファイル名（なければ `null`）。アイコンを変えるたびに新しい名前で書き、古いファイルは保存後に消す。
  - 画像はキャラクターの id のフォルダに置く。ファイル名は自動の id ＋拡張子（元のファイル名は使わない）。名前を変えてもフォルダは動かない。
- 変更（作成・編集・削除・複製・並べ替え・カテゴリー名の変更・インポート）はその場で保存する。`characters.json` は一時ファイルに書いてから置き換える。
  - 編集の保存では、新しい画像を書いてから `characters.json` を書き、外した画像のファイルを最後に消す。
  - キャラクターを削除すると、そのフォルダ（画像）ごと消す（元に戻せない）。
- **アプリの外での編集**: Character Manager を開く時・ツールの一覧を開く時・変更する時に毎回ファイルから読み直す。
  - `categories` にないカテゴリーは、最初に出てきた順に末尾へ足す。
  - 形の正しくない項目（id・名前が文字列でない、id がフォルダ名に使えない）は読み飛ばす（次に書く時に消える）。本文がなければ空、`images` がなければ 0 枚。
  - `images` のうち、ファイル名として正しくないもの・ファイルがないものは外す（次に書く時に消える）。`icon` も同じ（なければアイコンなし）。
  - フォルダにあって `images` にないファイル、`characters.json` にない id のフォルダは、表示も削除もしない。
- JSON として読めない時: 上書きせずに `characters.broken-<YYYYMMDD_HHMMSS>.json` へ退避し、空の一覧で読み込む（画像のフォルダには触らない）。
  注意トースト「キャラクターファイル（characters.json）が壊れていたため <退避先> に退避し、登録キャラクターなしで読み込みました。」

## Character Manager（`features/character-manager/`）
- 左端の列のマネージャーのグループにある「Character Manager」（person アイコン）で開く。**表示モードの 1 つ**（Workspace / Parallel / Overlay / Prompt Manager と排他）。
  - もう一度押すと Normal に戻る。ほかのモードのボタンを押すとそのモードに切り替わる。開いている間はアイコンを選択中の色にする。
  - 開くたびにファイルから読み直す（カテゴリーの選択は「すべて」、検索は空、編集欄は空に戻る）。
- 画面: 左サイドバーにカテゴリー一覧（見出し「CHARACTERS」）、メイン領域にキャラクター一覧（左）と編集欄（右）。右サイドバー（AI パネル）は閉じる。
  ```
  ┌CHARACTERS ⟳ ⇪ ⇩┬[検索______][+ 新規]┬ 名前 [            ]          ┐
  │ すべて       5 │ ■ 主要キャラ       │ カテゴリー [      ]           │
  │ 主要キャラ   3 │ ⋮⋮ [顔] 花子       │ プロンプト本文                │
  │ モブ         1 │ ⋮⋮ [顔] 太郎       │ ┌───────────────────────────┐ │
  │ 未分類       1 │ ■ モブ             │ └───────────────────────────┘ │
  │                │ ⋮⋮ [人] 店員       │ アイコン [顔] [変更][外す]    │
  │                │                    │ 画像（3 枚）                  │
  │                │                    │ [追加口: クリック / D&D]      │
  │                │                    │ [画1][画2][画3]               │
  │                │                    │         [削除][複製][保存]   │
  └────────────────┴────────────────────┴───────────────────────────────┘
  ```

### カテゴリー一覧（左サイドバー）
- Prompt Manager と同じ（再読み込み・インポート・エクスポートのボタン、「すべて」・カテゴリー・「未分類」の行と件数、
  名前の変更・統合・未分類へ移す、行のドラッグでの並べ替え、キャラクターの行をカテゴリーの行へドラッグして移す）。
  確認の文言は「プロンプト」を「キャラクター」に置き換えたもの（例「「<旧>」のキャラクター N 件を「<新>」にまとめますか？」）。

### キャラクター一覧
- Prompt Manager のプロンプト一覧と同じ（検索・「すべて」での見出し・選択中の色・並べ替えの条件）。
- 検索は名前とプロンプト本文に含まれる文字（大文字・小文字を区別しない）。
- 行はアイコン（56px 四方。なければ人のアイコン。画像があってもアイコンを作るまでは人のアイコン）と名前。ツールチップは本文（空なら名前）。
- 0 件の時: 登録が 0 件なら「登録されたキャラクターはありません。「+ 新規」から作成できます。」、検索・絞り込みで 0 件なら「条件に合うキャラクターはありません。」

### 編集欄
- 何も開いていない時は「キャラクターを選ぶか「+ 新規」で作成してください。」
- 項目: 名前・カテゴリー（候補付きの自由入力。空欄の表示は「未分類」）・プロンプト本文・アイコン・画像。ボタン: 削除・複製・保存（新規の時は「破棄」）。
  変更があると見出しに「未保存」を出す。画像の追加・削除・並べ替え・画像ごとの本文、アイコンの作成・変更・外すも「未保存」の変更で、「保存」で書く。
- **画像**:
  - 見出し「画像（N 枚）」。追加口はクリックでファイル選択（複数可）、またはドラッグ＆ドロップ。追加した画像は末尾に入る。
    PNG / JPEG / WebP 以外のファイルは追加せず、注意トースト「PNG / JPEG / WebP 以外の N 件は追加しませんでした」。
  - 画像は 1 枚ずつカードで並べる。カードは上にサムネイル（縦横比を保って枠に収める）、下にその画像の本文の入力欄（3 行、
    プレースホルダー「この画像の本文（任意）」）。カードをドラッグして並べ替え（本文の入力中はドラッグしない）、右上の × で外す
    （確認なし。保存するまでファイルは消えない）。
  - **サムネイルをクリックすると、画像を大きく見るウィンドウ**をアプリ内に開く（`shared/ui/image-viewer.ts`）。見出しに「画像 N」（新しい画像はファイル名）と ×。
    画像はウィンドウ（画面の 92% × 90%）に縦横比を保って収めて開く。Workspace の拡大表示と同じ部品で、ズーム・移動もできる
    （[flow-canvas.md](./flow-canvas.md)「拡大表示」）。見るだけのウィンドウで、×・Esc・ウィンドウの外のクリックで閉じ、編集欄は何も変わらない。
- **アイコン**（見出し「アイコン」。64px のプレビュー、なければ人のアイコン）:
  - ボタン「アイコンを作成」（あれば「アイコンを変更」）で下の「アイコンの切り取り」ウィンドウを開く。画像が 0 枚の間は押せない（ツールチップ「画像を追加すると作成できます」）。
  - ボタン「外す」でアイコンなしにする（アイコンがある時だけ）。
  - **アイコンのないキャラクターに画像を追加した時は、追加した最初の画像で「アイコンの切り取り」を自動で開く**（決定せずに閉じればアイコンなしのまま）。

### アイコンの切り取り（`features/character-manager/icon-cropper.ts`）
- 別ウィンドウ「アイコンの切り取り」（[app-shell.md](./app-shell.md)「別ウィンドウ」）。×・Esc・ウィンドウの外のクリックで閉じる（アイコンは変わらない）。
  下のフッターに「決定」。
- 上に元にする画像の選択（編集欄の画像のサムネイル。未保存の画像も選べる）。選んだ画像を中央に大きく表示し、その上に正方形の切り取り枠を重ねる。
- **顔の検出**: 画像を選ぶたびにバックエンドでアニメ顔を検出する（下の「顔の検出」）。
  - 検出中は画像の上に砂時計（回転するアイコン）・「顔を検出しています…」・「中断」ボタンを重ね、操作できなくする
    （枠の移動・拡大縮小、元画像の切り替え、「決定」はできない）。閉じることはでき、閉じると検出もやめる。
  - 「中断」: 検出をやめてウィンドウは開いたまま、枠は画像の中央（下の「見つからない時」と同じ位置）で手動で続ける。
    表示「顔の検出を中断しました。枠を動かして範囲を指定してください。」。元画像を選び直すと、その画像でまた検出する。
    バックエンドの処理は止めない（初回のモデルのダウンロードは裏で続き、次の検出から速くなる）。
  - 見つかった顔は点線の枠で示し、スコアの高い順の 1 件目に合わせて切り取り枠を置く。点線の枠をクリックするとその顔に合わせ直す。
  - 顔に合わせる時の枠: 顔の中心を中心に、一辺を顔の幅・高さの大きいほうの 1.6 倍（髪まで入るように）。画像からはみ出す時は内側へずらし、画像の短辺より大きくしない。
  - 表示「顔を N 件検出しました。枠を動かして調整できます。」/ 見つからない時「顔を検出できませんでした。枠を動かして範囲を指定してください。」
    （枠は画像の中央に、一辺を短辺の 6 割で置く）。検出に失敗した時（モデルを取得できない等）は注意トーストを出し、見つからない時と同じ扱いで続ける。
- **編集**: 枠の中をドラッグで移動、四隅のつまみをドラッグで大きさを変える（正方形のまま。最小は元画像で 16px）。枠は画像の外に出せない。
  右にでき上がりのプレビュー（256×256 を縮小表示）を出し、操作に合わせて更新する。
- 「決定」で枠の範囲を 256×256 の PNG にして編集欄のアイコンにする（保存は編集欄の「保存」）。元の範囲が 256px より小さい時は拡大する。

### 顔の検出（`backend/src/app/services/face_service.py`）
- モデル: deepghs/anime_face_detection の `face_detect_v1.4_s`（YOLOv8s・ONNX・MIT ライセンス・約 45MB）。rembg と同じ onnxruntime で CPU 実行する（1 枚 0.2 秒程度）。
  - しきい値 0.307（モデルに添付の値）、重なりの除去（NMS）は IoU 0.7。入力は長辺 640px に縮小して 32 の倍数に余白を足す。
- **モデルの入手**: 初めて検出する時に Hugging Face（版を固定した URL）から `models/anime_face_detect_v1.4_s.onnx` へ自動でダウンロードする（以後はオフラインで動く）。
  一時ファイルに書いてから置き換える。`models/` の場所は rembg と同じ（`CONFEITO_MODELS_DIR`）。
  - ダウンロードには時間がかかるので、フロントは検出が 3 秒を超えたら案内トースト「顔検出のモデルを準備しています（初回のみ。約 45MB をダウンロードします）」を出す。
  - ダウンロードできない時は 502「顔検出のモデルをダウンロードできませんでした。インターネット接続を確認してください。」（原文付き）。
- 検出の結果はアイコンの切り取り枠の初期位置にだけ使い、保存しない。
- **保存**: 「保存」または Ctrl+S（Character Manager 中は入力欄の中でも効く。ダイアログが開いている間は効かない）。
  - 名前が空・100 文字超、カテゴリーが 50 文字超、ほかのキャラクターと同じ名前の時は注意トーストを出して保存しない（本文・画像は空でもよい）。
  - カテゴリーを変えて保存したキャラクターは新しいカテゴリーの末尾へ。保存したキャラクターが今の絞り込みで見えなくなる時は、そのカテゴリーに切り替える（検索は空にする）。
  - トースト「キャラクター「<名前>」を保存しました」（新規は「作成しました」）。
- **+ 新規**: 編集欄を空にする。カテゴリーは左で選んでいるもの（「すべて」「未分類」なら空）。「保存」を押すまで一覧に入らない。
- **複製**: 保存済みの内容（画像・アイコンを含む）を「<名前> のコピー」（あれば「<名前> のコピー (2)」…）として元の直後に作り、複製を編集欄に開く。画像・アイコンのファイルもコピーする。
- **削除**: 確認「「<名前>」を削除しますか？」（画像があれば「画像 N 枚も削除されます。」を続ける）→「削除」。元に戻す機能はない。
- **未保存の変更がある時**の確認（別のキャラクターを開く・「+ 新規」・複製・ほかのモードへ切り替える）は Prompt Manager と同じ（「保存」「破棄」「キャンセル」）。
- 開いているキャラクターがほかのタブ・アプリの外で消されていた時（保存時）: エラートースト「キャラクターが見つかりません（削除された可能性があります）。」
  編集欄にある保存済みの画像がアプリの外で消されていた時（保存時）: エラートースト「画像「<ファイル名>」が見つかりません（削除された可能性があります）。」

### エクスポート / インポート（zip）
- **エクスポート**: 全件（カテゴリーの順・画像を含む）を zip ファイルとしてブラウザのダウンロードで保存する。ファイル名 `confeito-characters-<YYYYMMDD_HHMMSS>.zip`。
  中身は保存先と同じ形（`characters.json` ＋ `<id>/<画像>`・アイコン。画像ごとの本文も含む）。`characters.json` に `"format": "confeito-characters", "version": 2` を足す
  （version 1 = 画像ごとの本文のない以前の形。読み込むと本文なし）。
  トースト「キャラクター N 件を <ファイル名> に書き出しました」。
- **インポート**: ファイル選択（.zip）。zip の直下に `characters.json` があるものを読む（エクスポートした zip・`assets/characters/` の中身を zip にしたもののどちらも読める）。
  - 今の一覧に追加する（末尾へ。新しいカテゴリーはファイルの順で末尾に足す）。id は新しく振り直し、画像は新しいファイル名でコピーする。
  - 同じ名前のキャラクター（登録済み、またはファイルの中で先に出たもの）がある時は、まとめて 1 回だけ確認する:
    「N 件の名前がすでに登録されています。」→「上書き」「名前を変えて追加」「スキップ」「キャンセル」。
    - 上書き: カテゴリー・本文・画像（画像ごとの本文を含む）・アイコンを置き換える（カテゴリーが変わったら新しいカテゴリーの末尾へ。元の画像・アイコンのファイルは消す）。
  - アイコンは 256×256 の PNG にそろえて読み込む（画像として読めないアイコンは外し、読み込めなかった画像の枚数に数える）。
    - 名前を変えて追加: 「<名前> (2)」「<名前> (3)」…の空いている名前で追加する。
  - 名前が正しくない項目は読み込まず、件数を注意トースト「名前が正しくない N 件は読み込みませんでした。」で知らせる。
    zip にない画像・PNG / JPEG / WebP でない画像は外して読み込み、注意トースト「読み込めなかった画像 N 枚は外しました。」で知らせる。
  - トースト「キャラクターを読み込みました（追加 N 件・上書き N 件・スキップ N 件）」。
    zip として読めない時はエラートースト（「zip として読めないファイルです。」）、`characters.json` がない・読めない時もエラートースト。
- エクスポート・インポートは、編集欄の未保存の変更には触れない。

## API（`/api/characters`）
| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/characters` | `{categories, characters, warnings}`（カテゴリーの順・表示順のキャラクター。`images` は画像のファイル名の配列） |
| POST | `/api/characters` | multipart: `data`（JSON `{name, category, text, images}`）＋ `files`（新しい画像）→ `{character, warnings}`。末尾に作成 |
| PUT | `/api/characters/{id}` | multipart（POST と同じ形）で置き換え → `{character, warnings}` |
| DELETE | `/api/characters/{id}` | 削除（フォルダごと）→ `{warnings}` |
| POST | `/api/characters/{id}/duplicate` | 元の直後に複製（画像もコピー）→ `{character, warnings}` |
| PUT | `/api/characters/{id}/category` | `{category}` に移す（末尾へ）→ `{character, warnings}` |
| GET | `/api/characters/{id}/images/{file}` | 画像のファイル |
| GET | `/api/characters/{id}/icon` | アイコン（PNG。ない時は 404） |
| POST | `/api/characters/detect-faces` | multipart: `image` → `{faces: [{x, y, width, height, score}], warnings}`（元画像のピクセル座標・スコアの高い順。初回はモデルをダウンロード） |
| PUT | `/api/characters/order` | `{category, ids}` そのカテゴリーの中の順 → `{warnings}` |
| PUT | `/api/characters/categories/order` | `{categories}` カテゴリーの順 → `{warnings}` |
| POST | `/api/characters/categories/rename` | `{old, new}` 名前の変更・統合 → `{warnings}` |
| GET | `/api/characters/export` | zip（`Content-Disposition` にファイル名） |
| POST | `/api/characters/import/preview` | multipart: `file`（zip）→ `{count, conflicts, invalid, warnings}`（何も書かない） |
| POST | `/api/characters/import` | multipart: `file`（zip）・`on_conflict`（overwrite / rename / skip）→ `{added, overwritten, skipped, invalid, skipped_images, warnings}` |

- POST / PUT の `data.images` は保存後の画像の順で、要素は `{"file": "<保存済みのファイル名>"}`（そのキャラクターの画像）か `{"upload": <files の何番目か>}`。
  `images` にない保存済みの画像は消える。PNG / JPEG / WebP でない upload は 400「PNG / JPEG / WebP の画像ではありません（<ファイル名>）。」
- `data.icon` は `"keep"`（今のアイコンのまま。省略時）/ `"none"`（アイコンなし）/ `"upload"`（multipart の `icon` を新しいアイコンにする。256×256 の PNG に変換して保存）。
- 並べ替えで送った id の組がファイルの今の内容と合わない時は 409「キャラクターの一覧が変わっています。読み直してから並べ替えてください。」

# Cost Monitor（Gemini API の利用料）

Gemini API の利用料を知るためのダッシュボード。左端の列の Cost Monitor（browse_activity のアイコン）で開く表示モードの 1 つで、
メイン領域を覆い、AI パネルを閉じる。もう一度押すと Workspace に戻る（[app-shell.md](./app-shell.md)「画面構成」）。

## 前提: Gemini API の課金の仕組み（2026-10-04 時点で確認）
- Gemini API は前払い（Prepay）だけ（後払いは 2026-09-14 に廃止）。AI Studio でクレジットを買い、使った分がほぼリアルタイムで引かれる。
  クレジットはお金そのもの（購入した通貨の残高）。有効期限 12 か月。
- 料金表は USD 建て（トークン単価。思考トークンは出力テキストの単価）。円で払う場合は Google が換算する。
- **残高・利用額は API キーごとに分かれない。** 同じ請求先アカウントにつながるキー・プロジェクトで 1 つの残高を共有する。
- **残高を読む API はない**（残高と取引履歴は AI Studio の Billing でのみ見られる）。利用額は Cloud Billing の BigQuery エクスポートなら読めるが、
  GCP の設定（エクスポートと読み取り用のサービスアカウント）が必要で、最大 24 時間遅れ、プロジェクト単位（キー単位ではない）。
- そのため、API キーを複数の人・用途で使い回していても、アプリで正確に分かるのは「このアプリから使った分」だけ。

## 表示
上から次の順に並べる。

1. **ヘッダー**: 「Cost Monitor」、為替レート（`1 USD = [ ] 円`）、再読み込みボタン。
2. **期間**: 「7日 / 30日 / 90日 / 今月 / 全期間」の切り替えボタンと、その期間の日付（例「12/3（水） 〜 1/1（木）（30 日）」）。
   どれも今日まで（ローカル時刻の暦日）。全期間は最初の記録の日から（記録がなければ今日だけ）。
   グラフ・ツール別・モデル別・期間の合計と平均のタイルがこの期間で集計される（今日・今月のタイル、選んだ日の内訳、すべての履歴は期間によらない）。
   選んだ期間は押した時にユーザー設定（`costMonitor_range`、初期値 `30d`）に保存し、次に開く時も使う。
3. **このアプリで使った分**（バッジ「このPC」）
   - **数字のタイル**: 今日 / 今月 / 期間の合計（回数つき）、期間の 1 回あたりの平均、直前の実行（日時・ツール・モデル・状態）。
     単価未登録の回数は額から除き「単価未登録 N 回を除く」、概算を含む時は「概算 N 回を含む」と添える。
   - **日ごとの利用料**: 期間の毎日（使わなかった日も 0 で並ぶ）をツール別の積み上げ棒で、縦軸は円。2 ツール以上なら凡例（1 ツールなら見出しにツール名）。
     日付の目盛りは期間によらず 8 個程度（最後は「今日」）。列にマウスを乗せる（キーボードでフォーカスする）と、その日の合計（円・回数・USD）とツール別の額を出す。
     **列をクリック（Enter / Space）するとその日を選び**、下の「選んだ日の内訳」に出す。選んだ日の列は枠と背景で示す。
     色は固定の順（Nano Banana画像生成 → コマ分割 → ほかのツール）。色付きは 3 系列までで、それを超えるツールは「その他」にまとめる。
   - **ツール別の合計**（期間）: ツールごとの横棒（長さ = 最も多いツールに対する額）に、額・回数・期間の合計に占める割合・1 回あたりの平均を添える。
     下に「全体」の額・回数・1 回あたりの平均。
   - **モデル別**（期間）: 回数・入力 / 出力 / 思考トークン・画像枚数・利用料・1 回あたりの平均（額の多い順）。モデルは画像モデルなら通称（Nano Banana Pro など）。
   - **選んだ日の内訳**: 開いた時は今日。見出し（「12/29（月） の内訳」。今年でなければ年も）とその日の合計・回数、
     ツール別の横棒（割合つき）、モデル別の表、その日の実行一覧（新しい順。時刻・ツール・モデル・トークン・画像・利用料・状態のタグ）。
     使っていない日は「この日は Gemini を使っていません。」。
   - **すべての履歴**: 期間によらず新しい順に 50 件ずつ（「さらに N 件表示」）。日時・ツール・モデル・トークン・画像・利用料と、
     状態のタグ（結果なし（入力分は課金）/ 概算 / standard 以外の service tier）。
   - 記録が 1 件もない時は、グラフ以下の代わりに「まだ Gemini を使った記録はありません」。
4. **Google 側の記録（API キー全体）**（バッジ「未接続」）: 残高と API キー全体の利用額は AI Studio でのみ確認できる旨と、
   「利用額を開く（AI Studio）」（https://aistudio.google.com/spend）・「残高を開く（AI Studio）」（https://aistudio.google.com/billing）のボタン（新しいタブ）。
   残高はアプリに表示しない（手入力も受け付けない）。
5. **注記**: 円の換算レートと目安であること、単価の確認日、検索の無料枠を引いていないこと、キャッシュも通常の単価で計算していること、平均の計算方法。

- **金額は円を優先して表示する**: 「約 37 円」を大きく、USD（= クレジット）を小さく横に添える（表の中は縦に並べる）。
  円は 10 円未満なら小数 1 桁、0 は「0 円」。USD は $1 以上で小数 2 桁、未満は 3〜4 桁（$0.134 / $0.0024）。グラフの縦軸とツールチップも円。
- **1 回あたりの平均** = 額 ÷ 単価のわかる実行の回数（単価未登録の実行は平均を下げないように除く）。単価のわかる実行がなければ「—」。
- 為替レートは画面で手入力（初期値 150、`settings/default_settings.json` の `costMonitor_usdJpyRate`）。変えるとその場で
  ユーザー設定に保存し、すべての額（過去分も）を換算し直す。0 以下・数でない値は注意トーストを出して元に戻す。外部から自動取得しない。
- 読み込むタイミング: モードを開いた時（選んだ日は今日に戻る）、再読み込みボタン、期間の切り替え、Cost Monitor を表示中にツールの実行が終わった時
  （期間の集計・選んだ日・履歴の最初の 50 件を読み直す）。読み込み中は前の表示を薄くして残す。日を選んだ時はその日の内訳だけ、
  「さらに N 件表示」は次の 50 件だけを読む。

## 記録（`backend/src/app/services/usage_service.py`）
- **記録するもの**: このアプリからの Gemini 呼び出しのうち、Gemini が HTTP 200 を返したもの（= 課金されるもの）。
  - Nano Banana画像生成（Interactions / generateContent）とコマ分割。画像がない応答（安全フィルタ等）も入力分は課金されるので「結果なし」（`no_output`）で記録する。
  - HTTP エラー（4xx / 5xx）・通信エラーは記録しない。
- **トークン数**: 応答の generateContent `usageMetadata`（prompt / toolUsePrompt / candidates（画像はモダリティ別）/ thoughts / cachedContent、
  `groundingMetadata` の検索クエリ数）、Interactions `usage`（total_input / tool_use / output（画像は `output_tokens_by_modality`）/ thought / cached、
  `grounding_tool_count`）から取る。
- **概算**: Interactions が画像のバイト列だけを返して使用量がない時は、モデルとサイズの画像 1 枚のトークン数（Pro 1K/2K 1,120・4K 2,000 など）で計算し、
  `estimated: true`（「概算」）にする。入力分は 0 として数える。それ以外で使用量のない応答は記録しない。
- **保存先**: SQLite の `data/usage.db`（表 `usage_records`。git 管理外・ユーザーデータ。消さない）。
  `data/` はアプリが自分で付ける記録の置き場（ユーザーが登録する素材の `assets/` とは分ける。`CONFEITO_DATA_DIR` で場所を変えられる）。記録は追加するだけで、書き換えない。
  読み書きは `services/usage_store.py` だけが行う（Web 版ではここをサーバーの DB に差し替える）。
  1 件の項目（API の `records` と同じ形。DB では `usage` の中身を列に展開し、検索用に `at_ms`（UTC のミリ秒）を持つ）:
  ```json
  {"id": "<自動>", "at": "2026-10-04T14:32:00+09:00", "user": "local", "tool": "Nano Banana画像生成", "model": "gemini-3-pro-image",
   "api": "interactions", "service_tier": "standard", "status": "success",
   "usage": {"input_tokens": 500, "cached_tokens": 0, "output_text_tokens": 0, "output_image_tokens": 1120, "thought_tokens": 200, "search_queries": 0, "images": 1},
   "cost_usd": 0.1378, "estimated": false, "prices_checked_on": "2026-10-04"}
  ```
  - `user` は今は常に `local`（将来の Web 版でログイン ID を入れ、利用者ごとに集計する。集計は `user` で絞る。画面に利用者の選択は出さない）。
  - 表の形を変える時は `PRAGMA user_version`（今は 1）で版を見て移行する。
  - DB を開けない・壊れている時は「利用記録（usage.db）を読み書きできませんでした…」のエラー（ファイルは消さない・退避しない）。
  - 書き込みに失敗してもツールの結果は返す（記録だけ失われる。コンソールにログ）。
- **集計はバックエンドで行う**（SQL）。ブラウザには全件を送らない。
  - `GET /api/usage/summary?now_ms&tz_offset_minutes&range`: 今日・今月の合計、期間（`7d` / `30d` / `90d` / `month` / `all`）の合計・日付・
    日別×ツール別の額（記録のない日も含む）・ツール別・モデル別の合計（額の多い順）、直前の記録。
    日・月の区切りは見ている人の時計（ブラウザが送る現在時刻と UTC からの差）で決める。
  - `GET /api/usage/day?date&tz_offset_minutes`: その日の合計・ツール別・モデル別・実行一覧（新しい順、1,000 件まで）。
  - `GET /api/usage/records?offset&limit`: 履歴を新しい順に 1 ページ分（`limit` は 200 まで）と全件数。
- **額**: 記録した時点の単価で計算して `cost_usd` に残す（あとで単価が変わっても過去の額は変わらない）。単価のないモデル・service tier は `null`（「単価未登録」）。

## 単価（`backend/src/app/services/pricing.py`）
- 公式の料金ページ（https://ai.google.dev/gemini-api/docs/pricing）の値をコードに持つ。適用開始日つきで、価格改定はコードを直す。画面に確認日を出す。
- 入力 = 入力トークン（ツール使用・キャッシュを含む）× 入力単価、出力 = （テキスト + 思考）× 出力単価 + 画像トークン × 画像出力単価。
  20 万トークンを超えるプロンプトは長文の単価（standard だけ。ほかの tier は通常の単価）。
- Google 検索: 1 回 $0.014（$14 / 1,000 回）。月の無料枠（5,000 回・プロジェクト共有）はアプリから使用状況が分からないので引かない（多めに出る）。
- キャッシュされた入力も通常の入力単価で計算する（多めに出る）。
- service tier: standard と、料金表にある flex / priority。

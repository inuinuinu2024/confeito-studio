# アーカイブ（作業データの保存）

表示と操作は Workspace（[flow-canvas.md](./flow-canvas.md)）、一覧と出し入れは Archive Manager（[archive-manager.md](./archive-manager.md)）。ここは保存の形式と規則。

- **アーカイブはアプリの内部データ**。ユーザーはアーカイブのフォルダを直接開かない前提で、アプリへの出し入れは次の 3 つで行う。
  - 取り込み: 画像読み込み（ツール・Workspace へのドロップ）、Archive Manager のインポート（zip）。
  - 取り出し: Archive Manager のエクスポート（アーカイブ丸ごとの zip。バックアップ・移行用）、Workspace の画像の書き出し（成果物）。
  - 名前の変更・削除: Archive Manager（削除は Workspace でも）。
- 書き出しと取り込みはブラウザのダウンロード / ファイル選択で行う（将来の Web 版でもそのまま使えるように。新しい機能では OS のダイアログを使わない）。

## 保存形式
- 1 アーカイブ = アーカイブのフォルダ（既定は `archives/`。下の「保存先」）直下の 1 フォルダ。中のファイル・サブフォルダはそのまま保存される（ZIP 形式は廃止）。
- **フォルダ名がアーカイブの ID**（キーの先頭）で、作った後は変えない。画面に出す名前は表示名（下の「表示名」）。
- 既存アーカイブへのファイル追加・上書きができる。名前に `..` `/` `\` を含むアーカイブ名、アーカイブ外を指すパスは拒否する。
- フロントエンドはエントリを `"<アーカイブ名>/<相対パス>"` のキーで扱う。
- ツールは作業ログ（log.txt）・エラー記録（error.txt）を書かない（[notifications.md](./notifications.md)「ログ」）。
  以前のバージョンが書いたものは残る（Workspace には画像以外を表示しない）。
- `<アーカイブ>/.flow.json`: Workspace でスタックごとに選んだ表示中の候補・コマの版（`{"selection": {スタック: 結果フォルダのキー}}`）と、
  コマ結合に使う画像のマーク（`{"merge": {コマの画像のキー: 画像のキー}}`）。
  壊れていれば選択なしとして扱い、次に選んだ時に書き直す。
- `<アーカイブ>/.archive.json`: 表示名と作成日時（下の「表示名」）。`.flow.json` と同じく内容一覧・Workspace には出さない。

## 表示名
- `.archive.json` に `{"format": "confeito-archive", "version": 1, "name": "<表示名>", "created_at": "YYYY-MM-DD HH:MM:SS"}` を持つ。
- 新しいアーカイブは作る時に書く。表示名はフォルダ名から先頭の `YYYYMMDD_HHMMSS_` を除いたもの（画像読み込みは画像名、ツールの結果で作った時はツール名）。100 文字に切り詰める。
- `.archive.json` のない（以前のバージョンで作った）・読めないアーカイブは、フォルダ名を表示名に、フォルダ名の日時（なければ更新日時）を作成日時にする。
  名前を変えた時に作る。
- **表示名は重ねない**: 新しく作る・インポートする時に同じ表示名があれば「<名前> (2)」「<名前> (3)」…。名前の変更で同じ名前を指定したら拒否する（409）。
  ゴミ箱から戻したアーカイブは元の表示名のまま（その間に同じ名前ができていても変えない）。
- 表示名の条件: 前後の空白を除いて 1〜100 文字、制御文字を含まない。フォルダ名のような文字の制限はない。
- Workspace のドロップダウン・Archive Manager・トースト（画像読み込み「「<表示名>」を作成し…」、アーカイブの削除）は表示名を出す。

## エクスポート / インポート（zip）
画面は [archive-manager.md](./archive-manager.md)。サービスは `services/archive_transfer.py`。
- **zip の形**:
  ```
  manifest.json        {"format": "confeito-archives", "version": 1, "exported_at": "...",
                        "archives": [{"id": "<フォルダ名>", "name": "<表示名>", "created_at": "...",
                                      "folder_mtimes": {"<サブフォルダ>": <更新日時（UNIX 秒）>}}]}
  <フォルダ名>/.archive.json   （ないアーカイブは表示名を書いて入れる。元のアーカイブは変えない）
  <フォルダ名>/…               （フォルダの中身すべて: 画像・info.json・.flow.json・Inputs/・Raw/ など）
  ```
  画像（PNG / JPEG / WebP / GIF）は圧縮し直さずに入れる。ゴミ箱（`.trash/`）は含めない。大きくなるので一時ファイルに作って送り、送った後に消す。
- **読める zip**: ① `manifest.json` のあるもの（エクスポートしたもの。manifest にないフォルダは外す）、
  ② manifest がなく、直下がアーカイブのフォルダのもの（以前の `archives/` の中身を zip にしたもの。`.` で始まるフォルダは無視）、
  ③ 直下にファイルがあるもの（zip 全体を 1 つのアーカイブに。ID と表示名は zip のファイル名）。
- **インポートの処理**（アーカイブごと）: 既存のものは上書きしない。
  1. アーカイブのフォルダ内の隠しフォルダ `.import-<乱数>/` に展開し、できあがってから本来の場所へ移す（途中で失敗したら一時フォルダを消す。半端なアーカイブは残さない）。
  2. ID は元のフォルダ名。使われていれば `_2`, `_3` …。表示名は zip の `.archive.json`（なければ manifest、どちらもなければ ID）で、重なれば「(2)」…。
  3. ID が変わった時は、info.json の `source` / `sources` / `settings`（コマ結合の差し替え・切り直しの元・原画など）と `.flow.json` の `selection` / `merge`（キー・値。スタックの ID の中のキーも）の
     `"<元の ID>/…"` を `"<新しい ID>/…"` に書き換える（Workspace の線・★・版・結合のマークがそのまま戻る）。
  4. サブフォルダの更新日時を manifest の `folder_mtimes` に戻す（info.json のない結果フォルダの日時に使われるため）。アーカイブのフォルダ自体は取り込んだ日時にする（一覧の先頭に来る）。
  - アーカイブの外を指すパス（絶対パス・`..`・ドライブ名）のファイルは外して数える（注意トースト）。
  - 1 つのアーカイブが失敗してもほかは読み込む（失敗は警告）。1 つも読み込めなければエラー。

## 画像の書き出し（成果物）
- Workspace で選んだ画像を、ブラウザのダウンロードで普通の画像ファイルとして保存する（[flow-canvas.md](./flow-canvas.md)「画像の書き出し」）。インポートの対象ではない。
- ファイル名: 開始画像は元のファイル名、結果の画像は `<結果フォルダ名>_<ファイル名>`（例 `20261002_200310_背景除去_nobg.png`。さらに下のフォルダも `_` でつなぐ）。
  ファイル名に使えない文字は `_`。
- 1 枚はそのまま、複数は 1 つの zip `confeito-images-<YYYYMMDD_HHMMSS>.zip`（フォルダなしで並べ、同じ名前は `<名前>_2.png` …）。

## 保存先（アーカイブのフォルダ）
- 既定はプロジェクト直下の `archives/`（`CONFEITO_ARCHIVES_DIR` で既定の場所を変えられる。テストと E2E は一時フォルダ）。
- 設定ウィンドウの「保存先」ページでフルパスを指定し直せる（[app-shell.md](./app-shell.md)「設定ウィンドウ」）。
  - 入力欄に直接入力するか、「参照…」で OS のフォルダ選択ダイアログ（バックエンドの PC、tkinter）から選ぶ。前後の空白と `"` は取り除く（エクスプローラーの「パスのコピー」をそのまま貼れる）。
  - 「変更」か Enter で切り替える。「既定に戻す」で既定のフォルダに戻す（既定のフォルダがなければ確認せずに作る）。
  - 指定したフォルダがない時は「フォルダがありません」の確認（「作成して変更」/ キャンセル）を出し、作成を選んだ時だけ作って切り替える。
  - 指定できないフォルダ（400 のエラートースト「アーカイブの保存先を変更できませんでした」）: 相対パス、ファイル、
    アプリのフォルダ（プロジェクト）とその親、プロジェクトの中のフォルダ（既定の `archives/` とその中は除く）。
    アプリのファイルが Workspace に出て、削除（ゴミ箱への移動）できてしまうのを防ぐため。
  - 欄の下に「使用中: <パス>（既定）」（既定でない時は「使用中: <パス>　／　既定: <パス>」）。フォルダが見つからない時はその旨を注意の色で出す。
- **切り替えても中身は移動しない。** 元のフォルダのアーカイブはそのまま残り、元に戻すとまた表示される。
  ゴミ箱（`.trash/`）もそれぞれのフォルダの中にあり、起動時に空にするのは使用中のフォルダのゴミ箱だけ。
- 切り替えた時: Workspace の選択を外し、削除の Undo の履歴を消して（前のフォルダの削除は戻せない）、新しいフォルダの
  一番新しいアーカイブを表示する。トースト「アーカイブの保存先を「<パス>」に変更しました」。
- 保存先はユーザー設定（`settings/user_settings.json` の `app_archivesDir`。空 = 既定）に書き、起動時に読む。
  保存されたフォルダが使えない（相対パスなど）時は既定のフォルダを使い、「保存先」ページにその理由を出す。
  保存されたフォルダが見つからないだけ（外付けドライブを外した等）の時はそのフォルダのままにする（一覧は空。保存する時に作られる）。

## ツールの結果の保存
全ツール共通のルール（バックエンド `archive_service.save_result`、フロント `features/tools/result.ts` の `saveToolResult`）。

- **保存先**: Workspace に表示中のアーカイブの直下に `<YYYYMMDD_HHMMSS>_<ツール名>/` を作り、結果をまとめて入れる
  （結果フォルダは入れ子にしない。どの画像から作ったかは info.json の `source` で表す）。
  アーカイブが 1 つもなければ新しいアーカイブ `<YYYYMMDD_HHMMSS>_<ツール名>`（表示名 `<ツール名>`）を作る。
  - 例外: 画像読み込みは毎回新しいアーカイブ `<YYYYMMDD_HHMMSS>_<画像名>`（表示名 `<画像名>`。取り込んだ画像と `.archive.json` だけを入れる）。
- **名前**: ツール名は表示名（`コマ分割`, `コマ切り直し`, `コマ結合`, `背景除去`, `Nano Banana画像生成`）。同じ名前のフォルダ・アーカイブがあれば
  `_2`, `_3` … を付けて、既存のものを上書きしない。
- **info.json**: 結果フォルダに 1 つ置く（画像読み込みのアーカイブには置かない）。
  ```json
  {
    "tool": "背景除去",
    "created_at": "2026-10-02 20:03:00",
    "source": "20261002_200000_page/page.png",
    "settings": { "alpha_matting": true, "fg_threshold": 240, "bg_threshold": 10, "erode_size": 10 },
    "outputs": ["nobg.png"]
  }
  ```
  - `source`: 入力のキー（処理した画像。コマ結合は対象のコマ分割の結果フォルダ）。Nano Banana画像生成 は null（入力は Inputs/ の参照画像）。
    ただし Workspace で選んだ画像を原画にした時はその画像のキー。Workspace の線と、同じ入力 + 同じツールの結果を重ねる単位はこれで決まる。
  - `sources`: 入力の画像が複数ある時だけ、そのすべてのキー（コマ結合: 貼った画像を、差し替えたものも含めてコマの順に）。
  - `settings`: そのツールの設定値。`outputs`: info.json 以外に保存したファイル（結果フォルダからの相対パス）。
- **入力のコピーは残さない**（元画像はアーカイブにあるため）。Nano Banana画像生成 の参照画像（`Inputs/`）は、アーカイブ外から追加したものもあるので残す。原画も、ファイルから設定した時だけ `Inputs/Original.*` に残す。
- **保存後**: Workspace を読み直し、結果の画像（コマ分割は全コマ）を選択する（[flow-canvas.md](./flow-canvas.md)「選択」）。

| ツール | 結果フォルダの中身 |
|---|---|
| コマ分割 | `01.png`, `02.png`, …, `panels.json`, `info.json` |
| コマ切り直し | `<コマのファイル名>`（例: `02.png`）, `info.json`（Workspace のコマの切り直しから。[tools/panel-split-merge.md](./tools/panel-split-merge.md)） |
| コマ結合 | `<YYYYMMDD_HHMMSS>_コマ結合.png`, `info.json` |
| 背景除去 | `nobg.png`, `info.json` |
| Nano Banana画像生成 | `<YYYYMMDD_HHMMSS>_Nano Banana画像生成.png|.jpg`, `Inputs/Image1.*` …, `Inputs/payload.json`, `info.json`（原画がある時は `Raw/generated.*`、ファイルから設定した原画の `Inputs/Original.*` も） |

## 削除と Undo
- Workspace の削除（何を消すかは [flow-canvas.md](./flow-canvas.md)「削除」）と Archive Manager の削除は、対象をゴミ箱（`archives/.trash/`）へ移す。完全には消さない。
  - アーカイブ → `.trash/<アーカイブ名>/`。
  - アーカイブ内のファイル・サブフォルダ → `.trash/.items/<アーカイブ名>/<元の相対パス>`。空になったフォルダは消し、
    アーカイブ自体が空になったらアーカイブのフォルダも消す（中身はゴミ箱にある）。
  - フォルダとその中のファイルを同時に指定した場合は、フォルダごと 1 回だけ移す。
  - ゴミ箱に同じ場所の古いものがあれば上書きする。
  - 対象（アーカイブ・開始画像・結果フォルダ）を 1 つずつ順に移す。一部が失敗しても、移せたものは削除済みとして Undo の対象になる。
  - トースト: 移せたもの 1 件「「<名前>」を削除しました」（アーカイブは表示名、結果フォルダはフォルダ名）、複数「<N> 件を削除しました」。
    移せなかったものはエラートースト「「<名前>」を削除できませんでした」（複数は「<N> 件を削除できませんでした」。最初の失敗の原文付き）。
  - 削除後は Workspace を読み直し、削除したものを表示から消す（選択は解除）。
- ゴミ箱はアプリ起動時（バックエンド起動時）に中身をすべて完全に削除する。消せなかったもの（他のアプリが開いている等）は残し、
  バックエンドのログに警告を出す。このため削除の取り消しは同じ起動中だけ。
- **Undo**（Workspace のツールバーの元に戻すボタン、Ctrl+Z）は、削除した分をゴミ箱から元の場所へ戻すだけの機能。Redo（やり直し）はない。
  - ボタンはアイコン `undo`、ツールチップ「削除を元に戻す (Ctrl+Z)」。
    戻す削除がない間と、削除・元に戻す処理の最中は薄くして押せない（Ctrl+Z は処理中でも受け付け、順番に実行する）。
  - 1 回で 1 回分の削除を、新しい順に戻す。例: ファイル1を削除 → フォルダaを削除 → ファイル2を削除 の後、
    Undo でファイル2が戻り、もう一度 Undo でフォルダaが戻る（さらに Undo でファイル1）。1 回の削除で複数を選んでいた時は、その全部を戻す。
  - 削除と Undo は 1 つずつ、操作した順に実行する（連打しても前の Undo が終わってから次を戻す）。キーを押し続けても 1 回分だけ。
  - 空になって消えたアーカイブも作り直す。戻したアーカイブを Workspace に表示する（選択はしない）。
  - トースト: 1 件「「<名前>」を元に戻しました」、複数「<N> 件を元に戻しました」。戻すものがない時は「元に戻す削除はありません」。
  - **戻す先に同じ名前のもの**（削除後に作られたファイル・フォルダ・アーカイブ）がある時は、それに触らず戻さない
    （エラートースト「「<名前>」を元に戻せませんでした」、原文「同じ名前の…があるため元に戻せません」）。
  - **戻せなかったもの**（同じ名前がある・他のアプリが開いている等）は Undo の履歴に残り、次の Undo でもう一度戻そうとする
    （それより前の削除はその後）。ゴミ箱に見つからないもの（バックエンドの再起動で消えた等）は履歴から外す。
  - 設定ウィンドウ・ツールウィンドウ・ダイアログを開いている間と、入力欄・選択欄にフォーカスがある間は Ctrl+Z は効かない。
  - 履歴はページを再読み込みすると消える。対象は Workspace と Archive Manager の削除だけ（ツールの停止で結果フォルダを片付ける処理は含めない）。
- `.` で始まる名前はゴミ箱用に予約しており、アーカイブ名に使えない。

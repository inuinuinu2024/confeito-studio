# 通知（トースト）とエラー表示

アプリ全体の通知はトーストで出す。ログファイル（log.txt / error.txt）は書かない。

## トーストの種類
| 種類 | 用途 | 表示 |
|---|---|---|
| success | 成功 | ✔ アイコン。4 秒で消える |
| info | 案内、未実装機能の「開発中」 | ℹ アイコン。4 秒で消える |
| warning | 実行条件の不足・入力の誤り（画像が選ばれていない等） | ⚠ アイコン（黄）。4 秒で消える |
| error | 失敗 | ✖ アイコン（赤）。× で閉じるまで残る |

- 画面下中央に縦に積む（新しいものが下）。新しいトーストが来ても、表示中のトーストは消さない。
- 文言はすべて日本語。
- `alert()` は使わない（失敗はエラートーストで出す）。

## エラートースト
- 上から: 見出し（何が失敗したか）、日本語のメッセージ（理由・対処）、原文、「コピー」ボタン。右上の × で閉じる。
- **原文**: システム側のメッセージ（HTTP ステータス、Gemini の応答、例外の文言）をそのまま等幅で表示する。
  高さを制限し、長い場合はスクロールする。原文がなければ出さない。
- 「コピー」で見出し・メッセージ・原文をまとめてクリップボードにコピーする。
- メッセージと原文の分け方（`shared/utils/error-message.ts` の `describeError`）:
  - バックエンドのエラー: メッセージ = バックエンドが日本語で書いたメッセージ（`detail` / `detail.message`）。
    原文 = `HTTP <status>` と `detail.raw_response`（Gemini の応答や例外の文言）。
    バックエンドが書いていない形式（FastAPI の入力検証エラーなど）は「リクエストの内容が正しくありません。」（5xx は「バックエンドでエラーが発生しました。」）＋原文 = 応答本文。
  - バックエンドに接続できない（`fetch` 自体の失敗）: 「バックエンドに接続できませんでした。起動しているか確認してください。」＋原文 = 例外。
  - フロントエンドが日本語で書いたエラー（`AppMessageError`）: その文言。原文は付けた場合だけ。
  - それ以外の例外: 「予期しないエラーが発生しました。」＋原文 = `<例外名>: <内容>`。
- バックエンドのエラーメッセージは日本語で書き、例外の文言や外部 API の応答は `raw_response` に分ける（docs/architecture/backend.md「エラー処理」）。

## ツール実行時（AI パネル・Workspace へのドロップ）
共通処理（`features/ai-panel/tool-runner.ts` の `runTool`）が 1 回の実行につきトーストを 1 つだけ出す。ツール自身は成功トーストを出さない。

| 結果 | トースト |
|---|---|
| 成功 | success「<ツール名>: <結果の要約>」 |
| 実行条件の不足 | warning「<ツール名>: <案内>」。失敗扱いにしない。ツールウィンドウは開いたまま |
| 失敗 | error。見出し「<ツール名>の実行に失敗しました」＋メッセージ＋原文 |
| キャンセル（ファイル選択を閉じた等） | 何も出さない |
| 停止（⏸） | info「<ツール名>: 実行を停止しました」（複数枚の時は「…（<N> 件中 <M> 件完了）」）。止めた 1 枚の結果は残さない（[ai-panel.md](./ai-panel.md)「実行の停止」） |
| 複数枚の実行（全部成功） | success「<ツール名>: <N> 件を処理しました」 |
| 複数枚の実行（失敗あり） | error。見出し「<ツール名>: <N> 件中 <M> 件成功・<K> 件失敗しました」＋最初の失敗のメッセージ＋原文（[ai-panel.md](./ai-panel.md)「まとめて実行」） |
| ほかのツールの実行中 | warning「<ツール名>: 「<実行中のツール名>」の実行が終わってから実行してください」。実行しない |

- 実行条件はツールを押した時ではなく、実行した時（設定のないツールは押した時、設定のあるツールは実行ボタンを押した時）に確認する。
  サイドバーを開いたまま Workspace で選び直せるため。
- 成功の要約（「<結果フォルダ>」は保存したフォルダのキー。[archives.md](./archives.md)「ツールの結果の保存」）:
  - 画像読み込み「「<アーカイブの表示名>」を作成し、<ファイル名> を読み込みました」
  - コマ分割「N コマに分割し、「<結果フォルダ>」に保存しました」
  - コマ結合「「<結果フォルダ>」に結合画像を保存しました」
  - 背景除去「「<結果フォルダ>」に保存しました」
  - Nano Banana画像生成「「<結果フォルダ>」に画像を保存しました」
- 拡大表示・比較で画像を読み込めなかった時: error「「<ファイル名>」を読み込めませんでした」（原文なし）。
- 実行条件の不足の案内:
  - 画像を選んでいない（コマ分割・背景除去など）「キャンバスで対象の画像を選択してください。」
  - コマ結合「キャンバスでコマ分割の結果（コマ、またはコマから作った画像）を選択してください。」

## ログ
- ツールの実行結果・エラーを log.txt / error.txt に書かない。`<日時>_<ツール名>_error` のようなエラー用アーカイブも作らない。
- 以前のバージョンが書いた log.txt / error.txt はユーザーデータなので消さない（Workspace には表示しない）。
- 入力や中間データの記録はログではないので残す: Nano Banana画像生成 の `Inputs/`（参照画像と payload.json）、コマ分割の `panels.json`、
  各結果フォルダの `info.json`（[archives.md](./archives.md)「ツールの結果の保存」）。

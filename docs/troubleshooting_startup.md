# トラブルシューティング記録: アプリ起動失敗と "Failed to fetch" 問題

**発生日**: 2026-08-12  
**対象**: Confeito-Studio (Vite フロントエンド + FastAPI バックエンド)

## 症状
ユーザーが提供された `.lnk` ショートカット（デスクトップアプリ風の起動）からアプリを立ち上げると、フロントエンドからバックエンドへのAPI通信時（例: Nano Banana Pro機能の実行時）に `Failed to fetch` エラーが発生する。
手動でバックエンドサーバー (`uv run python -m uvicorn src.app.main:app`) を起動した場合は正常に動作する。

## 原因調査で判明したこと

この問題の背後には、2つの独立した根本原因が潜んでいました。

### 1. VBScript と Windowsプロセスグループによるバックグラウンドプロセスの強制終了
当初、ショートカットは `start-app.vbs` を経由して `cmd.exe /c` でバックエンドとフロントエンドをバックグラウンド起動（ウィンドウスタイル: `0` = 非表示）していました。
しかし、Windowsのプロセス管理において、`WshShell.Run` や PowerShell の `Start-Process -WindowStyle Hidden` で起動したプロセスツリーは、親スクリプトが終了したタイミングで一緒に子プロセス（`uvicorn` や `npm/node`）も巻き込んで終了してしまう（あるいは正常にプロセスがスポーンされない）という挙動を示しました。

その結果、起動直後にバックエンドプロセスが死んでしまい、フロントエンドからのAPIリクエストが `Failed to fetch` となっていました。

### 2. バックエンド (`main.py`) の `.env` パス解決ミス
バックエンド起動時の環境変数読み込み処理において、パスの解決に誤りがありました。

```python
# 誤 (5階層上 = プロジェクトルートのさらに上を指していた)
root_env = Path(__file__).parent.parent.parent.parent.parent / ".env"

# 正 (4階層上 = confeito-studio/ 直下)
root_env = Path(__file__).parent.parent.parent.parent / ".env"
```
これにより、環境変数が正しく読み込まれない問題が隠れていました（直接的な起動失敗の原因ではありませんでしたが、APIキー等が読み込まれず後続の処理でエラーになる状態でした）。

## 解決方法

以下の修正を行い、ショートカットからの完全なデタッチ起動（バックグラウンド起動）を安定化させました。

### 1. WMI (`Win32_Process.Create`) を用いたプロセスの完全デタッチ
VBScript や通常のコマンドプロンプト呼び出しを廃止し、**PowerShell経由で WMI (`Win32_Process.Create`) を使用してプロセスを生成**する方式 (`start-app.ps1`) に移行しました。
WMI を経由して作成されたプロセスは、呼び出し元のスクリプトのプロセスツリーから完全に独立するため、ランチャースクリプトが終了してもバックエンド/フロントエンドのサーバーが生き残るようになります。

### 2. VBScript の廃止とショートカットの直接化
不安定な `start-app.vbs` を削除し、`create-shortcut.bat` で生成する `.lnk` ショートカットのターゲットを直接 `powershell.exe -File start-app.ps1` を叩くように変更しました。

### 3. デバッグ用ログトグルの実装
将来のトラブルシューティングに備え、`start-app.ps1` の先頭に `$LOG_ENABLED` フラグを実装しました。これを `$true` に変更するだけで、起動時の各プロセスのPIDやエラー出力（stderr）を `setup/` ディレクトリ内のログファイルに記録できるようにしました。

## 今後の推奨事項
- 同様の「裏でサーバーを立てる」構成をとる場合、Windows環境では `Win32_Process.Create` を用いたデタッチ起動が最も確実です。
- 開発サーバーのプロセスは、現状「ブラウザのタブがすべて閉じられた際」にフロントエンドの Vite プラグイン経由で終了される仕組みになっています。もしプロセスが残留した場合は、手動で `node` や `uv` (python) のプロセスを終了する必要があります。

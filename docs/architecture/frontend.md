# フロントエンド設計方針

## UI構成とコンポーネント設計
- React/Vue等のフレームワークは不使用。各コンポーネントは `create*()` 関数が `HTMLElement` を返すDOM APIベースのパターン。
- **レイアウト**: CSS Grid (`manga-grid`) で画面全体を3列3行構成に分割。
- **表示・選択仕様**: アーカイブ非選択時はキャンバスにPSDのみを表示し、アーカイブ選択時は全面をアーカイブ表示へ切り替える（スプリットビュー廃止）。レイヤーツリーとアーカイブリストの選択状態は排他制御とする。
- **スタイリング**: `variables.css` の Vanilla CSS Custom Properties（デザイントークン）で一元管理。
- **Feature-based アーキテクチャ**: 機能単位（Vertical Slice）でトップレベルフォルダを分割。共通処理は `shared/` に隔離し循環依存を回避。

## 状態管理・キャッシュ仕様
- グローバルな状態はバックエンドのAPIまたはIndexedDBを通じて管理。
- **PSDキャッシュ**: `lastPsd` はファイル実体ではなく File System Access API の `fileHandle` のみを保持。巨大PSDのメモリ制限回避のため、ロード時は `{ totalMemoryLimit: undefined }` を指定。
- **アーカイブキャッシュ**: 起動時は非展開で一覧表示し、展開時に画像をフェッチする遅延読み込み。

## その他仕様
- ブラウザの全タブを閉じると開発サーバーも自動終了するViteプラグインを利用。
- ズーム倍率は最大1000%。拡縮は物理サイズ変更と `overflow: auto` によりネイティブスクロールを利用。
- リストの下にあるレイヤーが上に重なって見える（逆順描画）仕様。
- **PSD自動復元**: 起動時に自動で読み込みを試行し、ブラウザのUser Activation制約がある場合はユーザーの初回クリック時にバックグラウンドで権限要求と復元を行う。
- **キャンバス描画とリサイズ**:
  - Compare Modeなどにおいてアーカイブ画像を読み込み、キャンバスの描画領域サイズが拡張される場合、コンテナのアスペクト比を維持するため必ずズームの再計算を行う。
  - PSDの描画時は常に「PSD本来のキャンバスサイズ」でクリッピングを行い、領域外にはみ出して配置されたレイヤーのピクセルが描画されないように制御する。
